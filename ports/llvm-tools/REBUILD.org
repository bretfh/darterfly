#+title: Rebuilding Clang TableGen inside Darterfly
#+date: 2026-10-18
#+startup: overview

* Build boundary

This build compiles clang-tblgen, its LLVM libraries and the selected C++
runtime inside Darterfly. Each compiler, assembler, archiver, linker and
resulting executable runs in an isolated native world. Low supplies the
existing shared libsa implementation for the final executable.

The selected closure contains 248 translation units:

- 22 Clang support and generator sources.
- 155 LLVM Support sources, including C and BLAKE3 assembly.
- 12 LLVM TableGen library sources.
- 6 LLVM Demangle sources.
- 52 selected libc++, libc++abi and libunwind sources.
- Darterfly's existing startup assembly.

Native llvm-ar creates Support, TableGen, Demangle and runtime archives.
Native LLD links those libraries and the direct generator objects with
fresh Low-generated libsa. No imported LLVM or C++ runtime object is used
as an input to that link. The OS itself and the three native build-tool
seeds remain bootstrap inputs.

* Source bundle and configuration

The exporter reads the pinned LLVM 19.1.7 Ninja graph and the existing
runtime source manifest. It rejects unknown compiler options and absolute
input paths outside the declared source/sysroot mappings. It preserves
source selection, target defines, include ordering, language versions,
optimization, exception/RTTI choices and section/visibility settings.
Driver-only dependency flags, warnings and debug information are omitted.
The frontend explicitly enables GCC-compatible predefined macros with
-fgnuc-version=4.2.1, as the driver does; upstream BLAKE3 needs __GNUC__
to select its x86 intrinsics.
The runtime builds use -O1; LLVM and Clang sources use -Os.
LLVM Support warns that futimes/futimens and malloc statistics are absent
in this configuration. This build does not add those facilities.

The native compiler now exposes upstream -cc1as as well as -cc1. Assembly
sources first run through the native C preprocessor, then the integrated
assembler. LLVM's response parser handles the complete argument lists;
there is no host compiler fallback.

The source-only bundle is under build/tblgen-rebuild/root. The exporter
rejects object, archive and shared-library files in that bundle. The base
OS disk still contains its normal SBCL/TCC bootstrap artifacts; the build
runner names only newly compiled objects under /work/tblgen when creating
this tool's libraries and executable.

inputs.json records SHA-256 hashes for the source/header bundle, shared
runtime sources and native tool seeds. plan.sexp contains explicit native
compiler commands and archive membership. The plan identity covers those
inputs and commands. Lisp reads it with read-time evaluation disabled.
Before creating a fresh disk, the harness verifies the prepared input
hashes and rejects changed sources, headers or tool seeds.

Ninja's dependency records for this selected compiler closure identify
three generated LLVM headers: Config/config.h, Config/llvm-config.h and
Config/abi-breaking.h. These remain configured on the host. The staged
libc++ __config_site and assertion-handler selection are also explicit
bootstrap configuration inputs. The exporter stages only those three
LLVM configuration headers. The compiler closure does not consume
generated TableGen output tables.

This closes source compilation for the selected tool and libraries. It
does not yet close local regeneration of the build graph, configuration
checks, compiler seed or the entire compiler/browser toolchain.

* Reproduce

First build the native tool seeds following [[file:README.org][the native tools guide]].
Rebuild the Clang seed after updating its frontend/assembler wrapper.

#+begin_src sh
cd ~/git/cl/darterfly-nyxt
guix shell -m manifest.scm -- \
  python3 tools/build-native-clang.py --skip-prerequisites
python3 tools/prepare-tblgen-rebuild.py
make test-native-tblgen-rebuild-guest
#+end_src

The test creates a disposable 2 GiB APFS build disk at
build/tblgen-rebuild.img and boots the actual Darterfly kernel/image in
four-vCPU, 4 GiB QEMU/KVM. The disk retains /work/tblgen after the VM exits.
The runner logs each source before compiling it and records completion
only after successful exit and an ELF output check.

For an interrupted run with unchanged inputs, resume the existing disk:

#+begin_src sh
DARTERFLY_TBLGEN_RESUME=1 make test-native-tblgen-rebuild-guest
#+end_src

Resume refreshes the Lisp runner and the native-image loader source. It
does not update the LLVM/runtime source bundle, plan or compiler seeds on
that disk. Changing those inputs calls
for a fresh default run. Completion records are an aid for continuing the
same build, not a substitute for recording the original compilation log.
The runner rebuilds archives and relinks on every invocation.

* Repeated compiler launch and supervisor memory

Each native launch reads a fresh executable snapshot. Repeated 50 MiB
compiler snapshots exposed supervisor heap fragmentation: after 95
successful compilations, allocating the next snapshot exhausted the
1 GiB Lisp heap. Minor collections had promoted transient large vectors.

The native loader now requests a full collection before snapshots of
16 MiB or larger. It retains the 128 MiB executable bound and rereads the
file on every launch, so replacing a compiler remains visible. The checked
file length also bounds the allocation if the file grows during collection.
This adds
a collection pause to large program launches. It does not increase the
heap, add another allocator or claim general memory-pressure recovery.

* Qualification

The test runs the rebuilt generator on declaration, statement and
attribute definitions and compares its output with the pinned host build.
It then adds a local declaration definition, generates a header, compiles
a C++ client requiring that definition, links it with the rebuilt runtime
and runs it in another world.

A separate two-translation-unit runtime probe exercises constructors,
streams, allocation, RTTI, exceptions, threaded TLS, guards, clocks and
destructor ordering against the rebuilt runtime archive. Malformed TD
input must produce a diagnostic and remove its incomplete output; another
generator invocation must succeed afterward. Native children must be
reaped at completion.

After the VM stops, tools/export-tblgen-rebuild.lisp reads the APFS disk
and copies the built executable, libraries, generated tables and original
provenance into build/tblgen-rebuild/native. It does not alter the disk.
#+begin_src sh
make export-native-tblgen-rebuild
#+end_src

All 18 qualification checks passed, then passed again after reopening
the disk with all 248 completed objects retained. Recreated archives and
the relinked executable had the same hashes as the first successful run.
The guest synchronizes the filesystem before reporting completion.

The harness writes build/native-tblgen-rebuild-guest.log. This run also
retains its source-compilation transcript separately at
build/native-tblgen-rebuild-source.log. The validation record reports the
actual results and resumed build segments. Physical hardware,
all generator backends and a complete compiler rebuild are separate gates.

* What this increment establishes

Darterfly can load a static x86-64 ELF executable into an isolated world,
pass arguments and an environment, retain its termination status, and
reap it. The test executable can be compiled and linked inside Darterfly
using the existing TCC compiler and Lisp relocation engine.

This closes an initial part of R1 in [[file:SELF-HOSTING.org][the browser self-hosting plan]].
It does not close R1 as a whole. Neither Clang nor Chromium runs here yet.
The Nyxt and cl-cef sources are unchanged by this increment.

* Interfaces available now

#+begin_src lisp
;; Run in the system world's listener. ARGV includes argv[0].
(defparameter *child*
  (darterfly/worlds:spawn-native
   "/Users/darterfly/program"
   :argv '("program" "input.c")
   :envp '("LANG=C")))

;; NIL means running. Zero is a successful exit status.
(darterfly/worlds:wait-native *child* :nohang t)

;; Wait at most five seconds. A timeout leaves the child running.
(darterfly/worlds:wait-native *child* :timeout 5)

;; Cancellation and reaping are separate operations.
(darterfly/worlds:stop *child*)
(darterfly/worlds:wait-native *child*)
#+end_src

A successful wait consumes the status. Waiting a second time signals
ECHILD. A normal return from main becomes the low eight bits of its exit
code shifted left eight bits. A fatal fault occupies the signal field:
SIGILL is 4, SIGFPE is 8, SIGBUS is 10, and SIGSEGV is 11. Administrative
stop reports SIGKILL, 9. The first termination reason wins.

The kernel keeps 128 native status slots. Exited children retain a slot
until waited for, while their address spaces can already be reclaimed.
Exhaustion returns EAGAIN rather than silently dropping statuses.

These are world identifiers, not BSD process identifiers. The separate
[[file:BSD-NATIVE.org][BSD native-process integration]] now supplies execve/posix-spawn,
descriptor inheritance and actions, cwd, signals and wait4. The raw
spawn-native API shown here remains an explicit image-loading API; it
reads a file and does not enforce its executable permission bits.

An optional :port delegates one send right, named 1 in the child. A native
program can use the existing port protocol to request services. No port
is granted by default. The guest test exchanges a request and reply with
the Lisp supervisor and verifies the sender's world identifier.

* Executable and startup contract

The accepted image is ELF64, little endian, EM_X86_64, ET_EXEC. Program
headers must be in bounds, with at most 32 headers. PT_LOAD segments must
be ordered by address and must not overlap even at page granularity.
File lengths, memory lengths, alignment and address bounds are checked
before a world is allocated. The entry must be inside executable,
file-backed segment bytes.

The file and total mapped segment size are each limited to 128 MiB.
Segments must lie above the null page and below the user mmap area.
Initial mappings follow the ELF read/write/execute flags. The loader
rejects writable executable segments. This is not a system-wide ban on
later mprotect requests; it is the executable loader's initial contract.

BSS and stack pages begin zeroed. The stack is one MiB, grows down from
0x00007ff000000000, and is read/write but non-executable. Its initial
pointer is aligned to 16 bytes. A maximum of 64 KiB holds the argument
and environment strings plus startup words. Strings are UTF-8 and may
not contain embedded NUL characters.

#+begin_example
initial RSP -> argc
               argv[0] ... argv[argc-1]
               NULL
               envp[0] ... envp[envc-1]
               NULL
               AT_PAGESZ, 4096
               AT_NULL, 0
               strings and alignment padding
#+end_example

The assembly startup in [[file:../../tests/native-start.S][native-start.S]] calls
main(argc, argv, envp), then uses Darterfly's int 0x80 exit trap. Port calls
use int 0x82. This is Darterfly's ABI, not Linux's syscall ABI. An ELF file
format match alone does not make an existing Linux executable compatible.
The minimal auxiliary vector does not yet satisfy a general-purpose libc.

The loader rejects PT_INTERP, PT_DYNAMIC and executable-stack requests.
It now accepts one validated PT_TLS template inside a load segment; the
[[file:SHARED-RUNTIME.org][shared libsa runtime]] initializes static TLS for native threads. The
raw test startup above deliberately has no libc. Ordinary native tools
use libsa/crt0.S and the same libsa object as SBCL instead.

PIE, dynamic relocations, shared-library loading, C++ startup and exception
runtime support remain open. ELF acceptance is not C++ ABI qualification.

* Implementation

- [[file:../../src/kern/i386/native.lisp][Kernel ELF validation, segment loading and retained status slots]].
- [[file:../../src/worlds/worlds.lisp][Lisp spawn-native, argument packing and wait-native interfaces]].
- [[file:../../src/link/link.lisp][link-native, using the existing object relocation engine]].
- [[file:../../src/bsd/dev/i386/systemcalls.lisp][Supervisor calls 69 through 71, and native exit handling]].
- [[file:../../src/kern/i386/trap.lisp][Fatal faults stop the world and record a signal]].

Supervisor call 69 takes image address/length, stack address/length, and
an optional receive-port name. It creates an unprivileged world. Call 70
reaps a completed native world and returns its status, or negative EAGAIN
while it still exists. Call 71 validates an image without creating a
world. All three calls are restricted to the system world. They use the
kernel's numeric error convention: EAGAIN is 11, unlike the
BSD service layer's EAGAIN value of 35. Do not mix the two namespaces.

wait-native currently retries call 70 at ten-millisecond intervals. This
is a polling supervisor interface, not a new blocking wait syscall.
Cancellation uses the existing world-stop machinery and terminates all
threads belonging to that world. Normal exit now retains its code;
existing non-native worlds keep their previous stop/reclamation behavior.

Allocation failure handling is not yet complete OS resource isolation.
The existing page-table allocator can panic on global physical-memory
exhaustion, and native worlds do not have memory or CPU quotas. This
increment tests ordinary faults and repeated reclamation, not hostile
resource exhaustion. Compiler and browser admission must account for
that remaining kernel work.

* Tests and reproducibility

#+begin_src sh
make check
make test-native-guest
make test-local-sockets-guest
#+end_src

As with the other guest tests, a fresh checkout needs make sbcl first.
The native test builds a new kernel/image and boots four-vCPU QEMU with
a disposable root disk. It never changes the desktop's live disk.

[[file:../../tests/native.lisp][The host test]] builds the first fixture with Clang/LLD.
[[file:../../tests/native-guest.lisp][The guest script]] then exercises the actual kernel and:

- Checks argc, argv/envp termination, stack alignment, the auxiliary
  vector, initialized writable data and zero-filled BSS.
- Exchanges a port message between the native world and Lisp supervisor.
- Checks normal and zero exits, illegal instructions, invalid addresses,
  writes to executable code, and execution of stack bytes.
- Checks nonblocking wait, timeout, cancellation and double wait.
- Rejects malformed headers, overflowing lengths/offsets, wrong machine
  type, bad alignment, overlaps, W+X segments and dynamic/TLS images.
- Compiles the same C/assembly with target TCC, links it with link-native,
  writes an ELF file, and runs that rebuilt file in another world.
- Exhausts and reclaims the status table and repeats 140 launch/wait
  cycles with fixed input buffers to measure child-page reclamation.
- Checks that the Lisp supervisor remains responsive afterwards.

The compilation itself currently runs in the system world. The produced
executable runs in an isolated world. This is a local native-program
build/run loop; it is not a compiler rebuilding itself in a native world.

Validation on 2026-10-18: all 18 native guest assertions passed. The
140-cycle reclamation check observed a net difference of two free pages
in the whole machine, below its 32-page allowance for supervisor activity.
The seven existing socket guest assertions, eight raw-world assertions,
and make check also passed.

The transcript is saved to build/native-guest.log. Full boot logs live
under the test's temporary directory in native-console/. Do not count
host compilation or an image build alone as a successful guest test.

* Next steps toward the compiler and browser

1. [[file:CHILD-PROCESSES.org][Native callers and isolated SBCL now spawn and wait for children]].
   Broaden the process API from the tested static-tool subset to the
   selected compiler's needs. Public Low libsa spawn entry points,
   attributes, groups and exec replacement still need work.
2. Establish native libc startup and TLS, then qualify memory mapping,
   threads, atomics, filesystem operations and clocks against real tools.
   Add resource accounting and graceful allocation failure. The fixed
   address/static subset should grow only with executable tests.
3. Cross-seed a Darterfly-targeted C++ toolchain and runtime. First prove
   the compiler executes here and emits a program which links and runs.
   Add the linker/archive/COMDAT/relocation support required by those
   binaries. TCC remains available during bring-up.
4. Rebuild that compiler locally, including its generators and build
   tools. Test the resulting compiler by building and executing another
   program. This is the self-hosting gate, not simply importing Clang.
5. Bring up a minimal engine process, its subprocesses and CPU-rendered
   output. Qualify the pinned CEF/Chromium source build and generators
   locally, then attach the existing Nyxt backend with narrow adapters.

The larger acceptance gates and Guix inventories remain in
[[file:SELF-HOSTING.org][SELF-HOSTING.org]] and [[file:SBOM.org][SBOM.org]]. This change supplies the
first executable substrate for those gates; it does not replace them.

The guest rebuilt the image with these changes, booted Darterfly, and
compiled the expanded C probe with target TCC. The probe passed both in
world zero and in a separate world through the real port-vfs bridge.
Another isolated C client connected to a Lisp listener in world zero,
sent a byte, blocked in poll for a delayed response, and received it.
The listener finished successfully and the OS remained responsive.

Coverage includes socket creation/flags, socket fstat and pathname stat,
nonblocking accept, listen/connect/accept, local and peer addresses,
truncated and zero-capacity address output, malformed lengths, timeout
measurement, negative/invalid poll descriptors, EOF, half-close, hangup,
unlink/rebind and listener teardown. Host tests additionally cover queue
backpressure, blocking accept/connect wakeups, interruption, cancellation
of empty indefinite polls on world teardown, synthetic TCP queue state,
and rejection of truncated or inconsistent poll wire requests.

The expanded guest test caught C fstat still returning S_IFIFO for socket
descriptors. That path now reports S_IFSOCK, and the final guest run passes.

The Linux reference compiles with clang -Wall -Wextra -Werror and invokes
named_probe from tests/socketpair-probe.c. Darterfly-only checks cover its
256-entry poll bound and prevalidation of an invalid accept output pointer.
The legacy socketpair untouched-output assertion differs on this host's
Linux error path; the full combined probe is therefore not claimed as a
passing Linux reference in this increment. It remains enforced on Darterfly.

The complete host suite still fails only at the pre-existing undefined
DARTERFLY/INSTALL::FIRST-START-ENTRIES call, reproduced on the unchanged
parent during the first increment. No test was skipped or weakened.

Limits: named sockets currently require RAMFS (/tmp). No abstract Unix
addresses, descriptor/credential passing, complete socket options,
select/epoll, or native engine subprocess support was added. TCP/console
poll samples queues at 10ms intervals; those paths have not been qualified
under a browser workload. The guest tests establish cross-world functional
IPC, not a security qualification of the entire foreign-service protocol,
permissions, cancellation paths or resource limits.

No full guest/recovery suite or physical-hardware qualification was run.
Fresh make sbcl succeeded in the previous increment; this increment reused
that bootstrap and rebuilt its guest image through the test harness.

The guest test compiles its C source with target TCC and runs it both in
world zero and in an isolated world using port-vfs. It exercises nonblock,
close-on-exec flags, both directions, queued data before EOF, half-close,
peer close, invalid-family behavior and untouched outputs on failure.
Its final assertion verifies that the system remains responsive.

The independent Linux run caught a distinction in the error contract:
AF_INET is a supported family whose socketpair operation is unsupported,
so the implementation now returns EOPNOTSUPP there; an unknown family
returns EAFNOSUPPORT. This is covered by the host tests.

The complete host suite's failure is the onboarding test
FRESH-INSTALL-DOES-NOT-INHERIT-COMPLETED-SETUP. Its call to
DARTERFLY/INSTALL::FIRST-START-ENTRIES refers to an undefined function.
The unchanged parent was exported with git archive and its onboarding
suite reproduced that same failure: 16 passes and one failure. The
compatibility tests do not weaken or skip it.

No full ordinary guest suite, recovery suite, or physical-hardware
qualification was performed for this increment. Named Unix sockets,
readiness, descriptor passing, complete socket options/address queries,
dynamic libraries, native engine execution, and browser self-hosting
remain open.

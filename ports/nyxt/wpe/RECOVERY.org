#+title: Nyxt crash recovery through existing app worlds
#+date: 2026-10-19
#+startup: overview

* Qualification result

The complete run passed in one uninterrupted actual Darterfly QEMU guest:
ordinary Dock launch, HTTPS/JavaScript, input/navigation, quit/relaunch,
then all seven crash/hang injections, both retry-budget stops, manual retry
and final clean quit without restart. Each recovery checks removal of the
old native processes/worlds and WindowServer client. A recovered session
loads HTTPS and executes JavaScript again.

See [[file:recovery-evidence.json][the source/binary hashes and evidence index]] and
[[file:qualification-logs/nyxt-recovery-guest.log][the complete guest transcript]].
The accompanying regressions passed 88 host checks and 133 actual-OS checks
(47 native process checks plus 86 runtime, world and dynamic-loading checks).
The pinned Nyxt closure remains unchanged across all 5,615 source files.

The later [[file:dispatch-evidence.json][combined dispatch/recovery run]] repeats the entire sequence
after bounded queues and two kernel late-reply lifetime fixes. Its guest
transcript also rejects stopped supervisor workers; [[file:DISPATCH.org][the dispatch notes]]
describe those additional failures and regression coverage.

* Ownership and policy

The normal Dock entry still submits Nyxt to init. Nyxt owns the Lisp renderer
and its Layer client; its native UI, WebProcess and NetworkProcess descendants
use the existing BSD native process path and shared libsa. No second process
supervisor, runtime, allocator or TLS implementation is introduced.

The Nyxt job now uses init's existing =:keep-alive :crashed= policy, a minimum
10-second interval between starts, and =:most-exits 3 :window 600=. Two
failures may restart automatically; the third within ten minutes leaves the
job =:failed=. A normal exit leaves it =:stopped=. A subsequent explicit Dock
launch submits a new job and resets the budget. An unhealthy world stays
active until cleanup finishes, so a simultaneous Dock click cannot replace
its still-running supervisor. A long-lived session ages old failures out of
the existing rolling window.

Restart means a fresh application world using the original launch arguments.
It does not restore unsaved tabs, forms, downloads or WebKit ephemeral state.
Persistent profiles and session restoration remain separate work.

* Failure detection and bounds

The engine's public =web-process-terminated= signal becomes a fatal session
notification, except for a deliberate API termination. WPE's public GLib API
has no corresponding NetworkSession signal. The maintained port adds one
weak notification hook in =NetworkProcessProxy::networkProcessDidTerminate=;
Nyxt's engine supplies the implementation. Requested/idle network shutdowns
are excluded. Other engine harnesses retain a no-op default. This changes no
pinned Nyxt source and does not replace WebKit's process implementation.

Unhandled errors in Nyxt's default Bordeaux worker threads are reported to
the application loop, then unwind that worker. This includes asynchronous
startup errors, which previously entered SBCL's whole-runtime exit path from
a startup thread. Nyxt sources stay unchanged; the renderer uses Bordeaux's
existing default-special-bindings extension point.

The adapter reports failures with protocol operation 1106. A lost UI process
also breaks the socket. The application probes engine operation 18 every five
seconds; an unanswered RPC fails after the existing 30-second polling budget.
Only registered pending replies are retained, and every RPC removes its entry
on completion, error or timeout. Late replies are discarded.

Transport writers, including writer-lock acquisition, have a ten-second
budget. A partial header/body shares a ten-second deadline. An idle event
reader may wait until an event arrives, but cancellation wakes it. The native
engine now uses bounded nonblocking output with frame coalescing; a stalled
active packet or expired control packet fails the session. See
[[file:DISPATCH.org][the subsequent dispatch changes and combined-run qualification]].

Shutdown tolerates partial startup and repeated calls. It tries a graceful
engine stop with a one-second send budget, polls for exit for two seconds,
then uses the existing UIOP/BSD urgent termination path and polls for two more
seconds. It calls wait-process only after a nonblocking status check says the
process is dead. Reader/input and fixed dispatch-worker joins are limited
to two seconds each. The
engine socket pathname includes the owning startup thread's kernel TID.

Normal renderer shutdown also drains existing NFiles writers, with a
five-second deadline, before upstream quit clears the browser object. The
relaunch regression exposed a history writer still reading that object after
quit. This ordering fix uses NFiles' existing workers and leaves Nyxt's source
and persistence implementation unchanged.

Init supplies the outer bound if the app cannot complete cleanup or stops
making progress. It samples app health every five seconds with a two-second
world-eval timeout and stops a continuously unhealthy world after ten seconds.
Application progress becomes stale after sixty seconds. Before the application
health function is loaded, startup has a 240-second allowance. These are
scheduler-dependent bounds, not hard real-time guarantees.

World exit reuses =end-world-proc=: it prevents new children, kills and reaps
native descendants, closes their descriptors, and removes the world. The
existing WindowServer world-client cleanup removes its windows. Renderer
objects and unfinished callbacks belong to that terminating heap; recovery
never tries to reuse a half-failed session in place.

* Kernel termination boundary

Fault injection exposed a scheduler race below the browser: termination could
arrive while =sched-ast= parked or switched away from a thread. On resumption
it returned to user code without rechecking the termination flag. The thread
could then block again indefinitely. The paused-engine QEMU snapshot showed
six stopped-world threads waiting with =terminate-requested= still set.

The scheduler now checks termination again after those blocking operations.
The user-trap entry also rejects a stopped/terminating thread before dispatch:
a syscall already waiting for the kernel funnel must not create or block a
thread after world stop has visited the existing threads. Hardware interrupts
still receive their normal acknowledgement before the scheduler runs.

The native process regression creates shared-libsa pthread workers that sleep
or continuously create/join children. It kills each mode twelve times, pausing
half the worlds first, and checks both SIGKILL wait status and world removal.
The broader suite still rebuilds and executes its C probe inside Darterfly.

* VM map pressure during repeated launches

The extended run also reached the fixed VM-map entry limit. Protection
changes split ranges but never recombined identical neighbors. The VM map
now coalesces adjacent entries with identical protection and shared-mapping
flags. Mapping, unmapping and protection calls reserve their temporary split
capacity before mutation and return ENOMEM on exhaustion instead of panicking
the machine. Shared-file grants use the same capacity/coalescing helpers.

A native regression changes and restores protection across 4,096 pages,
exhausts genuinely distinct mappings, verifies a failed protection change is
atomic, releases the mappings and allocates again. Existing shared-memory
permission tests must also pass; coalescing must preserve read-only grants.

* Joined thread storage

Map coalescing prevented one failure mode, but the next complete run exposed
an underlying leak. Shared libsa's =pthread_join= waited for termination and
returned the value without releasing the thread record or static TLS.
The root supervisor serves BSD requests in short-lived SBCL threads; Nyxt
startup therefore accumulated hundreds of allocator arenas across launches.
Eventually the supervisor could no longer create a service thread.

Join now releases the thread record, its TLS allocation, and any stack owned
by libsa. It preserves stacks supplied by SBCL or other callers. TLS records
retain their original allocation pointer so over-aligned templates are freed
correctly. Failed thread creation releases partially allocated storage too.
Existing thread-local destructors still run on the exiting thread first.

The native regression joins 2,048 ordinary threads and 32 threads using a
caller-owned stack, checking that the latter remains writable after each
join. The dynamic-loading suite checks C++ TLS, destructors and threads
created before and after loading a library. Detached-thread storage still
has its pre-existing world-lifetime reclamation; improving that remains a
separate resource-lifecycle task.

* Reproduction

The failure harness runs only in the QEMU owned by =run-nyxt-app.lisp=. It is
not included in the optional application image. The fixture CA is added only
to the test disk, alongside the normal full system trust store.

#+begin_src sh
DARTERFLY_NYXT_RECOVERY=1 \
DARTER_HTTP_FIXTURE_LOG="$PWD/build/wpe-assessment/nyxt-recovery-origin.log" \
  sh ports/nyxt/wpe/with-http-fixture.sh \
  sh ports/nyxt/wpe/run-nyxt-app.sh \
  > build/wpe-assessment/nyxt-recovery-host.log 2>&1
#+end_src

This first repeats ordinary Dock launch, HTTPS, JavaScript, trusted/denied
callbacks, HID typing and navigation, clean quit and relaunch. The recovery
phase then kills the UI process, a WebProcess and the NetworkProcess
separately. It checks fresh worlds after the first two failures and a stopped
retry budget after the third, including absence of old native PIDs/worlds and
the old WindowServer client. A recovered session must load verified HTTPS and
execute JavaScript again.

After a manual relaunch, it stops the Lisp world, pauses the UI process without
closing its socket, and pauses the Lisp world itself. The latter exercises
init's external check. It verifies the same cleanup/budget, launches manually
again, injects an unhandled Bordeaux worker error, checks another bounded
recovery, and checks that ordinary Ctrl-Q does not cause a restart.

Run the OS regressions sequentially as well. These are the same seven tests
used for the recovery qualification (47 native-process checks and 86 other
kernel/world/dynamic-loading checks). They build and boot the current kernel, and the IPC
probe checks that read-only shared mappings still reject write upgrades.

#+begin_src sh
guix shell -m manifest.scm -- sh -c '
  export CL_SOURCE_REGISTRY="$PWD//:$GUIX_ENVIRONMENT/share/common-lisp//"
  export ASDF_OUTPUT_TRANSLATIONS="/:$HOME/.cache/common-lisp/darterfly/"
  sbcl --dynamic-space-size 8192 --no-userinit --non-interactive \
    --eval "(require :asdf)" \

      (darterfly/test::native-bsd-spawn-on-darterfly

       darterfly/test::threads-on-darterfly

       darterfly/test::init-keeps-world-jobs-alive-and-quarantines

#+end_src

=check-recovery-host.lisp= tests policy transitions and stalled writers,
partial packets, cancellation and lock contention. =record-recovery-evidence.py=
requires the guest/host pass markers and independent HTTPS origin requests,
verifies the pinned Nyxt source manifest, and hashes source, engines and logs.
It records evidence separately from the original browser and normal-app runs.

* Remaining merge gates

This qualification uses the existing resumed disk and dependency cache. It is
not a fresh source build/install or a long soak. It does not cover arbitrary
malicious pages, all socket truncation timings, simultaneous failures or
complete tab/session restoration.

Frame coalescing, bounded/ordered callbacks, broader lifecycle stress, durable
profiles and database locks, complete input and renderer APIs, and a clean
build/install remain on the merge-readiness checklist. The init failure state
is inspectable; a polished desktop crash notification/retry UI is still work.

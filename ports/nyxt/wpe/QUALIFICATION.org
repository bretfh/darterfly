* Current milestone (2026-10-19)

[[file:RENDER-QUALIFICATION.org][The full engine qualification]] now passes local, HTTP and HTTPS
rendering, JavaScript, certificate rejection and process cleanup under
normal init. Nyxt source compilation and its renderer extension remain
active work. Older milestones below describe the historical progression;
they do not supersede this measured state.

* Scope and current evidence

This work continues on codex/nyxt-guix-engine. It uses the same Low libsa,
allocator, TLS and native-world loader as existing native programs.
Guix supplies build tools; no Linux or macOS runtime is in the guest.

The original ASSESSMENT.org and evidence.json describe the baseline.
Their failed runtime probes are historical observations, not the current
qualification results. Keep that evidence separate from these results.

Upstream GLib 2.86.0, GObject and GModule build against libsa. A real GLib
and GObject program executes in its own native world in QEMU. It passes:

- Unicode normalization, PCRE2 regular expressions and GVariant values.
- GThread, GMutex, monotonic GCond and reader/writer try-lock operations.
- GObject type construction and signal emission through libffi.
- GMainLoop, descriptor polling and pipe readiness.
- g_spawn_async and g_child_watch_add, including child exit status.
- Directory rewind, binary substring search and temporary-file CLOEXEC.
- Clean process exit with the supervisor still responsive.

The successful log contains no GLib warnings. GModule is built, but this
probe does not qualify loading a GLib plugin from a shared object.

JavaScriptCore from WPE WebKit 2.54.1 executes in its own native world
using its public C API, C-loop interpreter, ICU and system allocator.
It passes arithmetic, 10,000-object allocation and reduction, typed
arrays, Map, regular expressions, Unicode normalization and Intl.Collator.
Two worker threads create independent JavaScript contexts while the main
thread runs 30 allocation/collection cycles. All contexts are released;
the process exits with status zero and the Lisp supervisor answers 42.

The native BSD regression passes all 43 checks. All ten runtime contract
probes pass, including native exec floating-point defaults and pthread
inheritance. GIO and the HTTP/TLS libraries now pass the follow-up
[[file:NETWORK-QUALIFICATION.org][network qualification]], including a verified public HTTPS page fetched
by libsoup in an isolated world. WebCore, WPEWebProcess, the WPE display
adapter and the Nyxt renderer extension are not yet running.
These results qualify the engine foundations, not a complete browser.

The current logs and input hashes are recorded in
[[file:qualification-evidence.json][the qualification evidence manifest]]. The baseline evidence.json remains
unchanged. The successful GLib run contains no GLib warnings.

* Runtime changes

The measured baseline gaps are fixed in shared libsa and kernel services:

- Monotonic condition deadlines retain the published four-byte condition
  variable ABI. The clock occupies the high bit of the wake sequence.
- sigsuspend atomically installs its temporary mask and restores the old
  mask through the actual signal return frame.
- Spawn transmits requested masks, default dispositions and inherited
  ignored dispositions through the existing spawn protocol and ELF auxv.
- Native BSD signal delivery reaches handlers in the owning world.
  SIGCHLD wakes GLib's child watcher. Ignored signals do not interrupt
  waits; default fatal signals preserve signal-death wait status.
- Native service requests can execute concurrently through a bounded,
  reusable set of workers. A blocked poll no longer prevents another
  native thread from writing its wake-up descriptor. Descriptors and
  mutations still use the existing BSD process and lock.
- Transport errors retain their errno. EINTR is not rewritten as EIO.
- Small missing libc functions and declarations reuse existing libsa
  mechanisms: rwlock try operations, directory rewind, C-locale collation,
  temporary-file flags and binary substring search.
- Extended-precision math and the public signal-context layout support
  upstream ICU and JavaScriptCore without a second runtime.
- Native executable startup resets x87 and SSE floating-point controls
  before constructors run. The first real JSC run exposed inherited Lisp
  traps: a JavaScript quiet NaN triggered SIGFPE. Native C programs now
  begin with masked exceptions and round-to-nearest; pthreads inherit
  their creating thread's environment.
- libsa's software fma preserves the exact product and sticky bits. It is
  a Low adaptation of musl's integer-significand algorithm, with its MIT
  notice retained in licenses/musl-COPYRIGHT. No musl runtime is linked.
  Host comparison against libm passes 400,000 deterministic random cases
  and 19,652 boundary cases across four rounding modes. Guest cases cover
  cancellation, subnormal results and overflow cancellation.
- Eight unchanged LLVM 19.1.7 compiler-rt helper sources provide 128-bit
  division and float/integer conversion. They are compiler arithmetic
  support, with no separate allocator, TLS or operating-system layer.
  tools/build-compiler-builtins.py records their source hashes.

The isolated-world probe tests the actual mask inheritance and a
50-cycle stop/resume handshake patterned on JavaScriptCore's collector.
That checks the signal machinery separately. The real JSC probe also
executes collection with multiple JavaScript contexts; this is not the
complete upstream collector or conformance test suite.

Guix source paths are recorded in build/wpe-assessment. Target compiler
wrappers exclude host headers and libraries. Configure link checks use

host tools were built with the pure Guix GCC environment from
ports/clang/host-manifest.scm. The target uses an explicit mh-darterfly
make fragment, not a Linux runtime configuration.

* Explicit upstream adaptations

Patches live in patches/. apply-patches.py applies them or checks that
exactly those patches are already present; it does not silently accept
an incompatible source tree.

GLib's initial core qualification option excludes GIO, introspection and
their auxiliary targets. The follow-up GIO build disables that option and
uses the raw DNS, socket, stream and spawn facilities described in
NETWORK-QUALIFICATION.org. The initial core-only evidence is retained.

The charset adapter embeds C/POSIX aliases, matching libsa's currently
supported locale. Unicode algorithms and explicit iconv conversions are
still upstream library code. This does not claim full libc locale data.

JavaScriptCore gets an explicit Darterfly OS identity and the actual
x86-64 signal register layout. It uses upstream generic event-loop and
POSIX thread/file implementations. Unsupported scheduling adjustments
are disabled. Process memory-pressure telemetry and paged-out-block
statistics are not provided. The initial static build uses upstream's
fallback bytecode-cache version path rather than ELF DSO enumeration.
Two direct header includes make Repatch.cpp compile without unified
builds. The JavaScriptCoreJIT object target is also required by the C-loop
interpreter despite its name; building it does not enable JIT compilation.

JIT, WebAssembly and the remote inspector are disabled for this first
interpreter qualification. Enabling them is not required to prove the
engine's basic native execution, and is not claimed by this result.

* Reproduction from prepared sources

The pinned source acquisition is recorded in ASSESSMENT.org and the
build/wpe-assessment source inventories. These commands assume those
sources and the existing C++ runtime seed are present.

#+begin_src sh
python3 ports/nyxt/wpe/build-libraries.py pcre2
python3 ports/nyxt/wpe/build-libraries.py libffi
python3 ports/nyxt/wpe/build-libraries.py libiconv
python3 ports/nyxt/wpe/build-libraries.py zlib
python3 ports/nyxt/wpe/build-libraries.py icu
python3 ports/nyxt/wpe/build-libraries.py glib
python3 ports/nyxt/wpe/build-glib-probe.py
sh ports/nyxt/wpe/run-glib.sh
python3 ports/nyxt/wpe/build-jsc.py
python3 tools/build-compiler-builtins.py
python3 ports/nyxt/wpe/build-jsc-probe.py
sh ports/nyxt/wpe/run-jsc.sh
sh ports/nyxt/wpe/run-contracts.sh
make test-native-bsd-guest
sh tools/check-libsa-fma.sh
#+end_src

Guest tests are sequential: this worktree has one shared boot-image and
monitor namespace. Do not run two guest harnesses here concurrently.
The qualification harnesses delete their own scratch disks after QEMU
exits. Logs remain in build/wpe-assessment and the scratch console dirs.

* Next browser gates

1. GIO and upstream HTTP/TLS libraries are now qualified in native worlds.
   Continue testing engine-specific contracts as WebCore uses them;
   persistent SQLite databases and complete GIO coverage remain open.
2. The [[file:RENDER-QUALIFICATION.org][software-rendering closure]] and WPEPlatform now run natively.
   Keep upstream subprocess boundaries and use the existing descriptor
   and named-socket services. Qualify actual dynamic-library loading as
   needed; the current GLib and JSC probes are static executables.
3. Run an engine harness in a separate world: first pixels from local
   HTML, script execution, input, navigation, then HTTPS. The compositor
   adapter consumes software-rendered buffers and supplies input events.
4. Connect that proven engine to a small Nyxt renderer extension. Keep
   Nyxt commands, buffers and modes upstream. This bridge is still work
   to do; passing the JSC C API probe does not port Nyxt's renderer.

Native compiler rebuilding remains the later self-hosting destination.
It is not a prerequisite for this cross-seeded native execution test.

#+title: Native Nyxt build: use Darterfly's existing Lisp environment
#+date: 2026-10-19
#+startup: overview

* Build boundary

The target is upstream Nyxt with a separate WPE renderer extension.
WPE's native engine qualification is recorded in
[[file:RENDER-QUALIFICATION.org][the rendering evidence]]. It does not establish that Nyxt runs.

The source build uses the existing isolated Lisp-world launcher, normal
init, shared libsa and native SBCL. The harness stages the pinned Nyxt
checkout and source dependencies without Linux binaries or host FASLs.
Nyxt's complete Lisp system now compiles and loads in that world and
exits with status zero. A clean-disk build passes without saved Nyxt
FASLs. A live Nyxt Lisp command runs, and its existing
HTTP client completes verified HTTPS requests, rejects four invalid
certificate classes, and recovers with another valid request. This includes its pinned IOLib and SQLite Lisp
bindings. This record covers the core build. The subsequent
[[file:NYXT-RENDERER.org][native browser qualification]] now connects Nyxt to WPE,
Darterfly windows and real input without changing its application sources.

The guest rebuilds standalone TCC, uses native LLD with shared libsa,
and compiles and runs CFFI's generated header probes. Upstream pkgconf
2.5.1 supplies pkg-config; upstream libfixposix 0.4.3 supplies IOLib's
foreign wrappers. Its spawn boundary maps to the existing posix_spawn
service, reusing upstream attribute and file-action objects.

Guest checks exercise relative readlinkat, directory iteration,
reentrant tokenization, confstr, nonblocking pipes, child working
directories, output redirection, descriptor inheritance and explicit
rejection of unsupported spawn attributes. The upstream IOLib Lisp API
launches pkg-config and captures its output. SQLite's Lisp API executes
queries and rolls back a transaction in memory. Persistent browser
storage is still unqualified: shared libsa deliberately rejects
unimplemented record locks instead of pretending they succeeded.

* Reuse OCICL's TLS

Darterfly already ships OCICL and its source dependency closure.
[[file:../../../src/apps/ocicl.lisp][The shared OCICL source-registration helper]] exposes those systems without
loading the package-manager application. Nyxt's build probe uses this
helper, loads pure-tls/cl+ssl-compat, and registers cl+ssl immutable before
resolving Nyxt's HTTP dependencies.

The OCICL CLI itself clears ASDF's registered systems for its executable
environment. Loading it into Nyxt therefore causes unnecessary dependency
reloads. The probe loads only the packaged TLS system and asserts that the
OCICL application package has not been loaded.

The extra central-registry entries are dynamically scoped. Loaded TLS
dependencies are registered immutable before restoring the registry, and
their names, versions and paths are logged as NYXT SHARED SYSTEM. This
keeps their definitions matched to resident code. Other dependencies
continue to resolve from Nyxt's pinned source checkout.

The guest asserts that CL+SSL:MAKE-SSL-CLIENT-STREAM exists and reports
NYXT OCICL TLS READY. A separate HTTP probe checks real requests and
certificate rejection. Shared-package adaptation and its host
reproduction are documented in [[file:../../ocicl/README.org][the OCICL source notes]].

The pinned library's session resumption is broken on host and guest.
A small source patch gates cached tickets out of verified connections,
so every new connection verifies a full certificate handshake. HTTP
keep-alive remains available. This Lisp TLS implementation supports
TLS 1.3 only; WebKit's engine supports the separately tested TLS 1.2/1.3.

Do not add another OpenSSL DSO build for Nyxt's Lisp HTTP stack. The
initial extra build script was removed. Keep certificate verification
and the existing CA bundle. Compatibility beyond successful loading must
be checked with Nyxt's actual HTTP users.

WebKit's existing native GIO TLS backend is a separate engine dependency.
It already passes the full engine HTTPS test. Connecting Lisp pure-tls
to GIO would introduce a new backend and is not part of this work.

* Commands and evidence

#+begin_src sh
python3 ports/nyxt/wpe/stage-nyxt-source.py \
  /tmp/darterfly-cef-reproduction/nyxt
sh ports/nyxt/wpe/run-nyxt-build.sh
#+end_src

Native inputs are seeded from Guix sources against the target headers:

#+begin_src sh
python3 ports/nyxt/wpe/build-nyxt-native-inputs.py pkgconf
python3 ports/nyxt/wpe/build-nyxt-native-inputs.py fixposix
python3 ports/nyxt/wpe/build-nyxt-native-inputs.py sqlite
#+end_src

The source roots and host tool profile are GC-rooted under
build/wpe-assessment. Recreate the source roots with Guix if needed:

#+begin_src sh
guix build --source libfixposix@0.4.3 \
  --root=build/wpe-assessment/fixposix-source
guix build --source pkgconf@2.5.1 \
  --root=build/wpe-assessment/pkgconf-source
#+end_src

Native tools and DSOs use shared libsa; no Linux
library is staged. SQLite uses the same 3.53.1 source as the WPE build.

The source manifest records Nyxt revision
cfa068ea781fe4866ae435c2950c00c5ec51cfee, dependency revisions and hashes.
It is written to build/wpe-assessment/nyxt-source-manifest.json.
The guest log is build/wpe-assessment/nyxt-build-guest.log. The measured
build is preserved in
[[file:qualification-logs/nyxt-source-build.log][the source-build log]] and [[file:nyxt-build-evidence.json][its evidence record]].
A failed qualification must remain a failure; NYXT LISP BUILD PASS records
compilation, while NYXT QUALIFICATION PASS and world exit zero are both
required for a successful probe. The harness preserves its build disk
and guest-produced FASLs.
An ordinary run creates a fresh disk; explicitly resume with:

#+begin_src sh
DARTERFLY_NYXT_RESUME=1 sh ports/nyxt/wpe/run-nyxt-build.sh
#+end_src

CFFI does not track changes in system headers. Set
DARTERFLY_NYXT_REGROVEL=1 for a resumed run to force IOLib's syscall
probes after changing their headers. The marker is removed only after
successful regeneration. Use a fresh disk after changing other layouts,
such as the socket or spawn structures. Failed probes retry on resume.

Resume refreshes source entries and the guest script using the existing
image updater. It refuses to update a disk held by another QEMU instance.
Close the diagnostic file normally before exiting on error,
so SBCL's abort-close does not delete the failure evidence.

* Optional spell checking

cl-enchant provides the SKIP-LOAD-ENCHANT restart around its foreign
library load. The source-build probe invokes only that named restart and
prints NYXT OPTIONAL ENCHANT UNAVAILABLE. Other native library failures
remain errors. This allows the core build to progress without patching
Nyxt or pretending that spell checking works. A usable launch must keep
spell checking disabled until Enchant and its dictionaries are installed.

* Next acceptance steps

1. Add a narrow WPE renderer extension, preserving Nyxt commands, buffers,
   modes, prompt/status views and internal URI schemes.
2. Connect software frames and input to Darterfly's window system.
3. Qualify persistent browser databases, including correct file locking.
4. Load a real HTTPS page through Nyxt's renderer, invoke a command, edit
   Lisp, and verify shutdown and restart under existing supervision.

Optional integrations must report absence honestly. Building the Lisp
core or showing an offscreen WebKit page alone is not a usable Nyxt launch.

* HTTP qualification commands

#+begin_src sh
DARTER_HTTP_FIXTURE_LOG="$PWD/build/wpe-assessment/nyxt-tls-host-origin.log" \
  sh ports/nyxt/wpe/with-http-fixture.sh \
  guix shell -m manifest.scm -- sbcl --no-userinit --non-interactive \
  --load ports/nyxt/wpe/test-ocicl-tls-host.lisp
python3 ports/nyxt/wpe/check-nyxt-origin.py \
  build/wpe-assessment/nyxt-tls-host-origin.log

DARTERFLY_NYXT_RESUME=1 \
DARTER_HTTP_FIXTURE_LOG="$PWD/build/wpe-assessment/nyxt-origin.log" \
  sh ports/nyxt/wpe/with-http-fixture.sh \
  sh ports/nyxt/wpe/run-nyxt-build.sh
python3 ports/nyxt/wpe/check-nyxt-origin.py \
  build/wpe-assessment/nyxt-origin.log
#+end_src

The local origin is only a test server on the QEMU host. Nyxt's Lisp,
TLS, sockets, compiler helpers and foreign libraries run in Darterfly.
The source-package identity is staged with the probe; changing that
identity invalidates pure-tls's guest FASLs even though Guix source
files have normalized timestamps. Other dependency caches remain usable.

The recorded final run uses a clean disk. Record successful qualification
and preserve its complete logs with:

#+begin_src sh
python3 ports/nyxt/wpe/record-nyxt-evidence.py --clean-disk
#+end_src

Use --clean-disk only after a build without DARTERFLY_NYXT_RESUME. The
recorder requires the guest markers, world exit zero, successful host
TLS checks, 75 native-service host checks and independent origin logs.

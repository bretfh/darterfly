* Architectural contract
[[file:ARCHITECTURE.org][The architecture contract]] follows bfh's October 19 corrections. Darterfly is a
live, personal Lisp workstation with a coherent desktop, persistent working state
and native compatibility. Worlds can organize arbitrary rooted objects and
activities; they are not obligatorily applications, processes or address spaces.
One hardware kernel manages kernel worlds. Per-world authority, environments and
service references do not imply duplicated kernels or drivers. Placement is an
explicit choice; existing init provides lifecycle supervision where needed.

Generic independently persistent object graphs are still a design/implementation
task. Whole-image save and kernel-world isolation are useful existing mechanisms,
not evidence that arbitrary object-subgraph persistence already works. WebKit's
native runtime remains part of the platform. Nyxt and Harbor are separate active
workstreams, not replacements for fixing the foundation.

* What this recovery repairs
The earlier 19 recovery commits are already on master through facd54d. They must
not be cherry-picked a second time. This follow-up starts there and fixes:

- Live saves queued behind an uninterruptible legacy console poll. The callback
  unwinds before delivering an interrupt; main-thread handoff is acknowledged and
  bounded before save preparation changes live state.
- Save/deploy ownership and failure cleanup. Competing operations cannot take
  another operation's record; a cold boot does not reopen a terminal record.
- Refused or incomplete transfers publishing new live sources. Incoming files
  are staged and checked before publication. This is not whole-tree atomic
  rollback if storage fails partway through publication.
- Confirmation racing pending installation, and a Wi-Fi health probe asking
  the card for an interface slot. Probe exceptions now prevent confirmation.
- Heap verification accepting an injected interior pointer. Aggressive tag/heap
  verification refuses the damaged save; the corruption test is retained.
- Native SBCL core loading through an unsupported general mmap request. Run
  archives now use the boot-file mapping path for their immutable core data.
- Duplicate APFS directory metadata in formatted root images. Repeated directory
  entries are coalesced before formatting; identical legacy duplicate keys are
  normalized on writable open and rewritten by normal copy-on-write commits.
  Conflicting duplicates are refused. This is not an offline filesystem checker.
- Shared guest FASL caches crossing worktrees. Guest core compilation uses the
  checkout's build/fasl directory.
- Recovery tests consuming a stale console prompt as the answer to a new query.
  The affected boot-menu and retained-activity tests delimit their evaluations.

- Suspend reporting: successful wake counts can exceed one; a refused kernel
  suspend returns zero without advancing the count. The hardware checker now
  distinguishes both and bounds reconnect attempts. Post-wake acceptance requires
  healthy observations separated by at least ten seconds. Timings start at the
  suspend RPC reply, not at the physical screen lighting up.
- A retained inactive Wi-Fi card no longer fails health while Ethernet is active.

* The UIOP byte difference is compiler state, not a target miscompile
The normalized host UIOP FASL has 693,086 bytes and the guest has 693,070. A clean
host SBCL bootstrap reproduces the larger output. In that same fresh host runtime,
allocating =(make-list 10000)= into a defparameter before compiling UIOP produces
the smaller output, byte-for-byte identical to the guest after the existing path
normalization and equal source timestamps. Pre-interning equivalent union types
also reproduces it. No Darterfly runtime participates in this host-only experiment.

SBCL interns equivalent type sets without preserving a prescribed order. Its
compiler's union type checks therefore depend on prior compiler/heap state.
The first disassembly difference is reordered character/pathname checks in
REIFY-SIMPLE-SEXP; instruction/branch layout and later register choices also
differ. The entire normalized guest FASL is reproduced by the host allocation
experiment, not just the first changed function. This is more than a timestamp
difference.

The native contrib test retains exact normalized comparisons for ASDF,
sb-rotate-byte, sb-md5, sb-posix and sb-bsd-sockets. For UIOP it loads the freshly
built module and exercises the SEXP converters over symbols, numbers,
characters, strings, pathnames, conses, vectors and nested combinations, plus
rejection of an unsupported object. Full-image/FASL reproducibility is not
claimed. Changing SBCL's type interning globally solely to force this comparison
would be a separate compiler change requiring its own qualification.

Host reproduction, using two fresh SBCL processes against the same source:
#+begin_src sh
build/sbcl-mt/run-sbcl.sh --noinform --disable-debugger --no-sysinit --no-userinit \
  --eval '(setf (sb-ext:readtable-base-char-preference *readtable*) :both)' \
  --eval '(compile-file #p"SYS:CONTRIB;ASDF;UIOP.LISP" :output-file "/tmp/uiop-a.fasl")' --quit
build/sbcl-mt/run-sbcl.sh --noinform --disable-debugger --no-sysinit --no-userinit \
  --eval '(defparameter *probe-allocation* (make-list 10000))' \
  --eval '(setf (sb-ext:readtable-base-char-preference *readtable*) :both)' \
  --eval '(compile-file #p"SYS:CONTRIB;ASDF;UIOP.LISP" :output-file "/tmp/uiop-b.fasl")' --quit
#+end_src

* Physical qualification in progress
Arraniz accepted source revision 3357e1f through the live-save path, advancing
from gen-57 to gen-58. Deployment 1U6CWF4-BROHPQNW reached terminal healthy after
90 seconds; the retained Lisp probe, Listener and running desktop survived.

Four RTC wakes returned cumulative counts 1 through 4. The old checker falsely
rejected count 2. Subsequent timing instrumentation showed a real radio failure:
Wi-Fi joined in 4–5 seconds, reported a firmware error about six seconds later,
then spent 45 seconds in failed scans before a retry joined without HT. The
65–69 second remote recovery is not a successful low-latency wake qualification.
The user connected Ethernet; remote access works at 10.42.0.194 and the live
probe still has its original gen-57 contents. Radio diagnosis continues over
Ethernet. Temporary timing wrappers were removed before any further save.

The radio was then isolated while Ethernet carried remote access. With identical
ARP traffic, legacy mode received 83 frames in 30 seconds; HT twice failed in
2 seconds. The retained UMAC error was 0x2010350b, last command 0x001d0516.
Command tracing showed two allocations for the same receive TID with no removal.
The corrected ADDBA path serializes session changes and removes an existing TID
before allocating it again. Removal is the full 16-byte firmware command, with
version-specific identifiers. DELBA now decodes the upper TID bits and checks the
peer's initiator bit. A failed removal retains ownership and prevents allocation.
The same HT test then received 82 frames over 30 seconds without firmware error.
This is a targeted driver repair, not a Wi-Fi throughput or full aggregation audit.

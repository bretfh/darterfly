#+TITLE: Reference platforms and capability evidence

* Evidence rules
Implemented means code exists. Automated coverage means a named test exists.
Verified means a dated passing report identifies the exact source/image and
configuration. A QEMU result never establishes physical hardware support.

Current dated results and release blockers: [[file:VALIDATION.org][validation report]].

* qemu-kvm-x86_64 (automated reference)
- Architecture: x86-64, QEMU q35, KVM, CPU host, four vCPUs, 4096 MiB RAM.
- Firmware: OVMF code and fresh snapshot of variables from pinned Guix profile;
  both file hashes and QEMU version are in each environment.json.
- Storage: virtio block ESP/root; tests also exercise emulated NVMe.
- Input: virtio keyboard/tablet; selected tests exercise xHCI USB HID.
- Network: virtio-net with user networking; selected tests exercise USB ECM.
- Display: UEFI GOP; headless QEMU with screenshot/monitor access.
- Boot: guest tests vary flags (stored in serial logs); measurement uses init
  with rd=disk2s1; release USB image uses rd=ram init.
- CPU host is intentional: performance comparisons require the same host CPU,
  host kernel, QEMU, firmware, vCPU count, and load conditions. VM measurements
  do not predict physical power consumption or battery life.

* Physical qualification report
Record UTC date, operator, image/source hash, generation, model and board,
firmware version/date, CPU/RAM, PCI/USB IDs, display mode, storage model,
boot flags, network adapter, AC/battery state, and ambient/workload conditions.
Omit serial numbers, MAC addresses, credentials, and unrelated personal data.

For each capability record PASS/FAIL/NOT-TESTED, procedure, raw logs, and issue.
Exercise cold boot, warm restart, install to a test disk, edit/build/save,
network loss/reconnect, USB hotplug, shutdown, fallback, backup/restore, and
long idle/load runs. Only mark supported capabilities after this report exists.

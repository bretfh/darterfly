* Recovery gate: blocked
The newly separated recovery suite ran 46 assertions: 42 passed and four failed
across two tests. See [[file:../build/recovery-validation/tests.log][recovery output]] and
[[file:../build/recovery-validation/consoles/][serial logs]]. Tests use disposable file-backed
virtual disks, not the physical workstation. The recovery workspace came from
an earlier captured baseline; its src/ files and Lisp tests are byte-identical
to the final measured baseline. Target checks confirm the watchdog syscall is
available and the heartbeat thread starts; the host-only guard does not skip it.

- REL-001: a-damaged-world-is-not-saved has three failed assertions. The injected
  pointer into an object's interior is reported as clean, save-generation accepts
  it, and pending-generation is created. The verifier/save implementation was not
  changed by the release tooling. Fix the verifier or underlying pointer invariant
  without weakening the corruption/refusal test.
- REL-002: erase-and-install-over-an-installed-system fails when the guest stops.
  The serial log reports a missed system-world heartbeat followed by a watchdog
  reset. Investigate thread restoration/startup and the reinstall path; retain
  watchdog protection and require this test to finish without an unexpected reset.

The full make release gate must remain failing until these are resolved. Physical
qualification, an identified arraniz inventory, and a clean committed full-suite
run are still required before promotion.

* Reproduction and remaining limits
The source archive, pinned channels, package closure, tool/firmware hashes, exact
QEMU arguments, stage logs, and build workspace are retained in the bundle.
See [[file:README.org][the release instructions]] for replay. A separate isolated recovery replay is
recorded in [[file:../build/recovery-validation/isolated.log][isolated.log]]: 13 assertions, nine passed,
four failed, reproducing both blockers outside the full recovery suite. The target
watchdog syscall and heartbeat were present before that replay. Bundle checksums
passed sha256sum --check --quiet SHA256SUMS.

Two independent development builds produced matching boot.efi and kernel hashes;
their source snapshots differed in tooling, so this is not a same-input full-image
reproducibility proof. Disk/core images differed. The manifest deliberately leaves
bit_identical_image_verified false. Remove nondeterminism and perform a controlled
same-source double build before changing that claim.

* Recovery follow-up, 2026-10-20
The historical results above are retained. The corrected full recovery suite now
passes 56/56 checks. REL-001 was reproduced and fixed with aggressive heap/tag
verification, without weakening its corruption/refusal test. Reinstall also
passes with the watchdog enabled; the historical REL-002 reset did not reproduce
at facd54d or in this follow-up, so no unproved causal explanation is claimed.

#+TITLE: Darterfly user journey and UX worklist

* Purpose
A person should know what the system is doing, what they can do next, and how
to recover. Review complete journeys in the Framework-hosted QEMU VM, then
repeat on physical hardware. A desktop screenshot alone is not an acceptance
test. This document complements [[file:ROADMAP.org][ROADMAP.org]] and [[file:TASKS.org][TASKS.org]].

* Journey map
| Phase | Observed before this pass | Intended experience | This pass / next action |
|-------+---------------------------+---------------------+-------------------------|
| Power on / firmware | No initialized display, black screen, then OVMF branding and boot text | Visible activity as soon as firmware permits; distinguish firmware time from OS time | Captured; firmware is outside the desktop's control |
| Boot selection | One-second text prompt for previous generation / safe start | Legible recovery choices with a discoverable way to pause and choose | Keep working recovery controls; design a proper boot chooser next |
| Kernel and runtime | Dark framebuffer with small diagnostic text | Continuous boot identity and honest stage messages; diagnostics available on failure | Captured; staged boot presentation remains open |
| Desktop handoff | Desktop appears before Dock and live welcome | Stable desktop, usable input, then the relevant next step | Measured visually; readiness coordination remains open |
| Live welcome | Small Try / Install window; temporary storage is unexplained | Explain live mode and temporary data; offer a safe default | Implemented clearer welcome; Try is the keyboard default |
| Try the system | Installer closes; no obvious way back | Explore freely; return to Install from a visible shortcut | Implemented live-only desktop installer shortcut |
| Choose destination | First NVMe disk is selected implicitly | Explicit disk identity and destructive confirmation; eventually choose among disks | Capacity and erase warning shown; multi-disk choice still needed |
| Install | Short changing text; errors can overflow the window | Real stage names, no invented percentage, readable errors and recovery | Implemented common layout; diagnostic details saved on error |
| Finish installation | Done closes the window; user must find restart | Clear media-removal instructions and a working power action | Implemented Shut Down without saving the live world |
| First installed start | Empty desktop; no setup | Optional, resumable assistant; supported settings take effect immediately | Implemented three steps: desktop color, clock format, orientation |
| Interrupted setup | No prior concept of setup state | Choices persist; resume unfinished step; completion suppresses autostart | Implemented versioned preferences and fresh-install marker |
| Later starts | Desktop; saved processes can resume | Restore choices and useful work without repeating onboarding | Test cold boots; saved-world resume needs additional qualification |
| Everyday use | Files, Terminal, Listener, Generations; several inert menus | Find apps and files, configure the machine, get help, undo mistakes | Explicit tasks below |
| Updates / recovery | Generations and boot recovery primitives exist | Explain changes, progress, fallback, and whether user data is safe | Separate end-to-end journey to review |
| Sleep / resume / shutdown | Power APIs and app menu actions exist | Predictable close/save behavior, feedback, and a clear way back | Separate VM + hardware qualification |

The current installation artifact is a USB disk image, not an ISO. Test boot
media as shipped; an ISO optical-media path would need its own qualification.

* First-start assistant delivered in this pass
1. Welcome / desktop color: Ocean, Forest, or Slate, applied to the running desktop.
2. Clock: 12-hour or 24-hour display, applied to the menu bar. This is not a
   time-zone selector.
3. Orientation: observed network connection status, Files and Dock guidance,
   and where to reopen setup. Offline use is allowed.

Back and Set Up Later are available. Choices and the current step are saved on
change. Finishing records completion; the next cold boot goes to the desktop.
The Files menu and /System/Applications/Setup.app reopen the assistant.
Tab, Enter/Space and Escape work in the assistant and installer page controls.
The destructive confirmation defaults to Back, not Erase and Install.

Fresh installs add /Library/Settings/setup-pending. Completed source-machine
setup preferences are excluded when copying a fresh installation. Existing
installations without this marker are not unexpectedly forced through setup.
Preferences live in /Users/darterfly/Library/Preferences/desktop.sexp, with a
versioned validated representation and a temporary-file/rename write followed
by disk flushing. Missing or malformed preferences fall back to defaults;
completion is never inferred from an unreadable file. This does not establish
power-loss durability of the underlying filesystem (see release blockers).

The assistant uses the existing single-user environment. It does not claim to
create secure accounts, set a password, encrypt the disk, select a keyboard
layout, or configure Wi-Fi. Those need real system support and separate flows.

* Prioritized next work
** P0: boot and first use
- [ ] UX-001: continuous boot presentation from loader to first composited frame.
  Keep serial diagnostics; add visible stage changes (loading system, starting
  services, preparing desktop), and a usable failure/timeout path. Do not show
  a fabricated percentage or leave a permanent spinner over a kernel failure.
  Acceptance: recorded cold boots, failed boot, safe start, and previous
  generation boot all explain their state. Measure firmware, loader, kernel,
  first frame, and first accepted input separately, over at least five runs.
- [ ] UX-002: coordinate desktop readiness. Show welcome only after the desktop,
  Dock, menu bar, and input are ready; avoid the current partially assembled
  desktop. Acceptance: repeated boots have no click-through or lost first key.
- [ ] UX-003: installer destination picker and preflight. Show model, size and
  identifying suffix; exclude boot media; require an explicit choice when
  multiple disks exist; show capacity errors before any erase.
  Acceptance: zero/one/multiple disks, too-small disk, USB + NVMe and missing
  payload have safe, navigable outcomes. Cover keyboard-only operation.
- [ ] UX-004: installation lifecycle. Prevent parallel installs; keep progress
  reachable if the window is closed; define cancel-before-write versus
  cannot-cancel-during-write; retain a useful failure report.
  Acceptance: close/reopen, quit attempt, write failure and device removal do
  not silently abandon work or incorrectly report success.
- [ ] UX-005: language, keyboard and time zone. Implement shared settings first;
  offer searchable choices, a typing test, and a time preview. Respect locale
  in dates/numbers. Acceptance: settings survive cold boot and saved-world resume.
- [ ] UX-006: network setup. Detect wired networking, list supported Wi-Fi
  networks, handle authentication/retry and offline continuation. Distinguish
  a link from actual Internet access. Do not block reaching the desktop.
- [ ] UX-007: accessibility before setup. Keyboard focus and traversal across
  all controls, display/text scaling, contrast, input assistance; establish
  an accessibility tree and screen-reader path. Test small/high-DPI displays.

** P1: a desktop someone can learn and keep using
- [ ] UX-008: consolidate setup choices into a discoverable Settings app; add
  timezone, display, sound, input, power and network only as backed by working APIs.
- [ ] UX-009: Files starts at the user's home with visible Documents/Downloads;
  breadcrumbs, app launching, open-with, safe delete/undo and a clear empty state.
- [ ] UX-010: replace inert menu items with working actions or disabled states;
  expose a consistent application switcher, launcher and keyboard shortcuts.
- [ ] UX-011: help and first useful task. Open/edit/save/reopen a document and
  build/run a Lisp example without requiring the user to discover shell internals.
- [ ] UX-012: account and lock-screen design only alongside real identity,
  authentication and isolation. Specify recovery and storage encryption first.
- [ ] UX-013: saved-world lifecycle. No duplicate first-run assistants after a
  save/resume; restored menu/Dock/settings agree; incomplete setup resumes once.

** P1: updates, failure and leaving the session
- [ ] UX-014: guided generation update, restart choice, failed-generation notice
  and rollback; distinguish system rollback from user-file restore.
- [ ] UX-015: visible app-not-responding recovery and force quit without losing
  the rest of the desktop; readable out-of-space/network errors.
- [ ] UX-016: coherent save/restart/shutdown UI, explain unsaved app state, and
  qualify actual suspend/resume on reference hardware.

* VM evidence and repeatable review
Baseline: release artifact from 20261018T014731Z-486cd3aa9317, booted with
snapshot writes. Host: Framework; QEMU q35/KVM, 4 vCPUs, 4 GiB RAM, OVMF,
1280x800 framebuffer, virtio input/network, disposable 4 GiB NVMe disk.
No physical disk was attached. No remote hardware was queried or existing credentials used.

Captures sampled the baseline cold boot at approximately 0.25-second intervals
plus screenshot overhead: firmware/blackness -> loader -> framebuffer text ->
desktop -> live welcome + Dock. These are visual observations, not latency
benchmark results. A fresh baseline install then booted directly to an empty
desktop, confirming the missing first-start handoff.

Validated on 2026-10-18 UTC:
- 1,201 host checks passed before the final caption-keyboard refinement.
- Final source: 23 focused checks passed (21 setup checks plus the existing
  USB graphical installer test). The final caption keyboard path is covered.
- Actual pointer/keyboard walkthrough passed: Try -> reopen Install -> erase
  confirmation -> install stages -> Shut Down. The shutdown occurred on the
  mouse-down event, before the test driver could send mouse-up.
- Fresh installed boot -> setup -> Forest color and 24-hour clock -> Set Up
  Later -> cold boot resumes step 2 -> finish -> another cold boot has no setup.
- Clicking a heading then using Tab/Enter works. The Files menu reopens setup;
  Escape dismisses it. A no-NVMe boot offers Back and allows trying the system.
- Visually inspected live welcome, erase confirmation, completion, first-start
  appearance, clock, orientation, normal desktop and Files-menu captures.

Reproduction: use the manifest.scm environment, load darterfly/test, and run
(fiveam:run! 'darterfly/test::onboarding) and
(fiveam:run! 'darterfly/test::install-from-the-desktop). Build USB media with
(darterfly/image:usb-image :boot-args "rd=ram init"). Use an isolated source
checkout and disposable >=4 GiB NVMe image; do not attach physical disks.
The recorded scripts in build/ux-review/scripts retain this session's exact
paths and QEMU configuration. Do not include ignored VM disk directories when
copying a development checkout into a test build.

Boot presentation/readiness, multiple destinations, installation close/quit
lifecycle, physical-device behavior, power-loss durability and saved-world
resume are not qualified by this pass. The existing release blockers remain
tracked separately; this work does not claim to fix them.
